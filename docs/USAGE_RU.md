# FastMock: Подробная инструкция

Добро пожаловать в документацию FastMock API Engine. Здесь описано, как использовать все возможности мок-сервера.

## 1. Загрузка спецификации (OpenAPI)

FastMock работает на основе вашей OpenAPI 3.0/3.1 спецификации. 
Есть два способа скормить спецификацию серверу:

### Способ А: При запуске (Auto-load)
Положите файл с именем `openapi.yaml` в корневую папку проекта. При запуске через `docker compose up` или `fastmock`, сервер автоматически найдет его и сгенерирует эндпоинты.

> 💡 **Быстрый тест:** В репозитории есть готовый пример `openapi.example.yaml`. Чтобы быстро проверить работу сервера, просто скопируйте его:
> ```bash
> cp openapi.example.yaml openapi.yaml
> ```
> И перезапустите сервер. Вы сразу получите готовые эндпоинты `/users` и `/products`.

### Способ Б: "На горячую" через Admin API
Если сервер уже запущен, вы можете загрузить новую спецификацию без перезагрузки:
1. Откройте Swagger UI: `http://127.0.0.1:8000/docs`
2. Найдите эндпоинт `POST /_admin/specs`
3. Загрузите ваш YAML или JSON файл.

## 2. Умная генерация данных (Faker)

Если в вашей OpenAPI спецификации не указан `example`, FastMock сгенерирует данные сам, ориентируясь на типы полей.

**Как он угадывает данные?**
* **По формату (format):** `uuid` -> валидный UUIDv4, `email` -> случайный email, `date-time` -> ISO8601 дата.
* **По названию поля:** Если поле называется `first_name`, сервер сгенерирует реальное человеческое имя. Если `phone` — номер телефона.
* **По базовому типу:** `string` -> случайное слово, `integer` -> число от 1 до 100, `array` -> массив из 1-3 элементов.

## 3. Сохранение состояния (In-Memory CRUD)

FastMock умеет запоминать данные на время работы сессии.
Например, если в вашей спеке есть `POST /users` и `GET /users`:

1. Отправьте `POST /users` с JSON-телом.
2. FastMock сгенерирует ему `id` (если его нет) и сохранит в памяти.
3. Отправьте `GET /users`, и в ответ вы получите массив, содержащий только что созданного пользователя!

> **Важно:** Данные хранятся в оперативной памяти (In-Memory). При перезапуске сервера они удалятся. Вы можете принудительно очистить базу, вызвав `DELETE /_admin/state`.

## 4. Симуляция сбоев сети (Chaos Engineering)

Мобильные и фронтенд-приложения должны уметь обрабатывать плохой интернет и падения бэкенда. FastMock позволяет симулировать это.

### Управление через заголовки (Per-Request)
Вы можете отправлять специальные заголовки с каждым запросом из вашего клиента:
* `X-Mock-Delay: 2000` — задержит ответ ровно на 2 секунды (2000 мс).
* `X-Mock-Status: 503` — заставит сервер принудительно вернуть ошибку 503 (Service Unavailable) вместо нормальных данных.

### Глобальное управление (Admin API)
Вы можете включить хаос для *всех* запросов сразу через Swagger UI (`PUT /_admin/config`):
```json
{
  "chaos_delay_ms": 1500,
  "chaos_error_rate": 0.2,
  "chaos_allowed_errors": [500, 502, 503]
}
```
*В этом примере: каждый запрос будет идти 1.5 секунды, и с вероятностью 20% будет падать с ошибкой 500, 502 или 503.*
